# خارطة تكاملات WAHA

هذه الوثيقة هي مرجع المنتج والتنفيذ للتكاملات الخارجية. وجود إضافة داخل Codex لا يعني أنها جزء من تطبيق WAHA؛ أي ميزة حقيقية للمستخدم تحتاج API أو SDK وترخيصًا يسمح بالاستخدام داخل منتج تجاري.

## التكامل الأول: Zotero

### القيمة للمستخدم

يستطيع مشترك خطة «باحث» ربط حساب Zotero واختيار مكتبة أو مجموعة، ثم:

1. استيراد بيانات المراجع إلى مشروع WAHA.
2. منع التكرار باستخدام DOI ثم ISBN ثم Zotero item key.
3. ربط المرجع بدليل أو مشكلة أو فجوة داخل المشروع.
4. تصدير المراجع التي أنشأها أو اختارها في WAHA إلى Zotero.
5. تنزيل مراجع المشروع بصيغتي BibTeX وRIS حتى من دون ربط حساب.

المرحلة الأولى لا تنسخ مرفقات PDF إلى WAHA ولا تستخدم مساحة تخزين Zotero الخاصة بصاحب المنصة. تبقى المرفقات في حساب المستخدم، ونخزن في WAHA البيانات الببليوغرافية والروابط والمعرّفات اللازمة فقط.

### مكان الميزة في المنتج

- صفحة الهبوط: بطاقة «قريبًا» تحت الميزات الحالية.
- الإعدادات أو الملف الشخصي: `الإعدادات ← التكاملات ← Zotero ← ربط الحساب`.
- مساحة المشروع: تبويب `المراجع` وفيه `استيراد من Zotero` و`تصدير إلى Zotero`.
- مرحلة الأدلة: زر `إضافة من مكتبة Zotero` بجانب البحث الأكاديمي.
- صفحة الأسعار: تذكر «مزامنة Zotero» ضمن خطة «باحث» عند إطلاقها، وليس قبل جاهزية التكامل.

### تجربة المستخدم

1. يضغط المستخدم «ربط Zotero».
2. ينتقل إلى صفحة تفويض Zotero ويوافق على أقل صلاحيات لازمة.
3. يعود إلى WAHA، ويعرض النظام المكتبات والمجموعات المتاحة.
4. يختار مجموعة ومشروعًا، ويشاهد معاينة قبل الاستيراد.
5. ينفذ الاستيراد وتظهر نتيجة: أضيف، حُدّث، تخطّي مكرر، وفشل.
6. يمكنه فصل الحساب وحذف رموز الوصول المخزنة في أي وقت.

### البنية البرمجية المقترحة

```text
Zotero OAuth 1.0a
  → /api/integrations/zotero/connect
  → /api/integrations/zotero/callback

  → /api/integrations/zotero/collections
  → /api/integrations/zotero/import

```

### قاعدة البيانات

#### `user_integrations`

- `id uuid`
- `user_id uuid`
- `provider text` وقيمته `zotero`
- `external_user_id text`
- `access_token_encrypted text`
- `permissions jsonb`
- `status text`
- `connected_at timestamptz`
- `revoked_at timestamptz`

قيد فريد على `(user_id, provider)`، مع RLS يمنع قراءة الرموز من العميل. فك التشفير يتم على السيرفر فقط.

#### `project_references`

- `id uuid`
- `project_id uuid`
- `user_id uuid`
- `provider text`
- `external_item_key text`
- `doi text`
- `title text`
- `authors jsonb`
- `publication_year integer`
- `publication_title text`
- `url text`
- `citation_data jsonb`
- `source_version integer`
- `synced_at timestamptz`

### الصلاحيات والخطة

- الربط والمزامنة: خطة «باحث» أو «مؤسسي».
- استيراد BibTeX/RIS يدويًا: يمكن إتاحته مجانًا بحد محدود.
- كل Route يتحقق من المستخدم ومن entitlement باسم `zotero_sync` على السيرفر.
- لا نعتمد على إخفاء الزر في الواجهة كحماية.
- نطلب قراءة المكتبة فقط في الإصدار الأول، ثم نضيف الكتابة بموافقة جديدة عندما يصبح التصدير إلى Zotero جاهزًا.

### متغيرات البيئة

- `ZOTERO_CLIENT_KEY`
- `ZOTERO_CLIENT_SECRET`
- `ZOTERO_CALLBACK_URL`
- مفتاح تشفير مستقل لرموز التكامل، ولا يرسل أي منها إلى المتصفح.

### الاعتمادية وحدود الاستخدام

- تحديد Zotero Web API v3 صراحة في الطلبات.
- تخزين مؤقت، ومزامنة تفاضلية باستخدام إصدارات المكتبة بدل تنزيل المكتبة كاملة كل مرة.
- حد أقصى أربعة طلبات متزامنة، واحترام `Backoff` و`Retry-After` وحالة `429`.
- سجل تدقيق لا يحتوي رموزًا أو بيانات حساسة.
- زر فصل الحساب يلغي الربط محليًا ويوجه المستخدم لإلغاء المفتاح من Zotero عند الحاجة.

### شروط القبول

- لا يستطيع مستخدم الوصول إلى تكامل مستخدم آخر.
- لا يظهر رمز Zotero في HTML أو logs أو استجابة API.
- الاستيراد المتكرر لا ينشئ مراجع مكررة.
- العربية وRTL تعملان في شاشة الربط والمعاينة.
- فشل Zotero لا يفقد بيانات المشروع ولا يمنع استخدام WAHA.
- يمكن تنزيل BibTeX صالح للمراجع المستوردة.
- اختبارات Route تشمل: غير مسجل، غير مشترك، OAuth غير صالح، rate limit، ومزامنة ناجحة.

### خارج نطاق الإصدار الأول

- تخزين أو مزامنة ملفات PDF والمرفقات.
- التعليقات التوضيحية على PDF.
- مزامنة لحظية ثنائية الاتجاه.
- مشاركة مكتبات المجموعات المؤسسية المعقدة.

## كيف نستفيد من بقية الإضافات والخدمات

| القدرة | فائدتها الحقيقية لـWAHA | طريقة التحويل إلى منتج |
|---|---|---|
| Supabase | حسابات، مشاريع، مراجع وصلاحيات | SDK داخل التطبيق، migrations وRLS |
| Stripe | بيع الخطط وفتح الميزات | Checkout + webhook + subscriptions + entitlements |
| Vercel | نشر ومراقبة وحماية التطبيق | إعدادات المشروع وFunctions وFirewall وObservability |
| Codex Security | اكتشاف الثغرات قبل وبعد التغييرات | فحص ثم إصلاح الكود والسياسات؛ ليست ميزة للمستخدم |
| Browser وChrome | اختبار الرحلات الحقيقية | اختبارات تسجيل ودفع وحفظ وتصدير على نسخة الإنتاج |
| Figma | تصميم واجهات متسقة | تحويل التصميم إلى React/CSS؛ ليست خدمة وقت التشغيل |
| Data Analytics | قياس إكمال الرحلة والتحويل للدفع | أحداث منتج موثوقة ثم تقارير داخلية، لا وعود للمستخدم |
| Consensus | تقييم جودة البحث والأدلة | يستخدم للتقييم الداخلي؛ دمج حي فقط عبر API وترخيص تجاري |
| PDF وDocuments | فحص جودة التصدير | مكتبات أو خدمة سيرفر داخل WAHA مع اختبارات بصرية |
| GitHub | مراجعة الكود وCI والمشكلات | عملية تطوير، وليست ميزة للمستخدم النهائي |
| Slack وFireflies | مقابلات العملاء وملاحظات الفريق | استخدام داخلي عند وجود فريق؛ لا يدخلان MVP |
| Biohub ESM وNGS | أبحاث الأحياء والتسلسل الجيني | خارج نطاق جمهور WAHA الحالي |

## ترتيب التنفيذ

1. إكمال اشتراكات Stripe وwebhook وentitlements.
2. تثبيت نموذج `project_references` والتصدير BibTeX/RIS.
3. تنفيذ Zotero قراءة واستيراد فقط.
4. قياس الاستخدام والأخطاء.
5. إضافة التصدير إلى Zotero بصلاحية كتابة منفصلة.
6. تقييم أي مزود بحث أكاديمي مدفوع بعد التحقق من API والترخيص والتكلفة.

## أمر جاهز لاستدعاء التنفيذ لاحقًا

> نفّذ المرحلة الأولى من تكامل Zotero حسب `docs/INTEGRATIONS_ROADMAP.md`: OAuth، قراءة المجموعات، معاينة الاستيراد، حفظ المراجع دون تكرار، entitlement للخطة المدفوعة، الاختبارات، وفحص الأمان. لا تنفذ مزامنة PDF أو الكتابة إلى Zotero في هذه المرحلة.
