# WAHA — مواصفات Workflow الأول ومعايير القبول

## النطاق

هذه المواصفات تحكم أول رحلة قابلة للاختبار. لا تضيف مرحلة «الاستبانة» قبل أن يثبت المستخدم نوع الدراسة ومنهجها ومتغيراتها.

| المرحلة | المدخل المطلوب | المخرج المحفوظ | معيار الفتح | فحص الجودة المطلوب |
| --- | --- | --- | --- | --- |
| 1. الفكرة | فكرة نصية ومجال اختياري | الفكرة ونتيجة الفحص | فكرة لا تقل عن وصف قابل للبحث | الوضوح، النطاق، المجتمع/السياق المحتمل |
| 2. المشكلة | فكرة مقبولة أو تحتاج تحسين | صياغة المشكلة | عنوان/فكرة محددة | هل تصف فجوة أو أثر مشكلة لا مجرد موضوع؟ |
| 3. الأدلة | مشكلة وعنوان عمل | دراسات مختارة بمصادرها | ثلاث دراسات موثقة على الأقل | لا تُعامل نتائج البحث كدليل إلا مع رابط/معرّف المصدر |
| 4. الفجوة | دراسات مختارة + مشكلة | فجوة محتملة مع سببها | أدلة كافية | تمييز «استنتاج من الأدلة» عن حقيقة مثبتة |
| 5. العنوان | فكرة + مشكلة + فجوة | عنوان معتمد وإصداره | عناصر البحث متسقة | العنوان يحدد الظاهرة/المجتمع/السياق بقدر كافٍ |
| 6. المشروع والتصدير | مخرجات المراحل السابقة | مشروع، سجل قرار، تصدير | لا مراحل إلزامية ناقصة | يصدّر فقط ما حفظه المشروع مع النسخ والمصادر |

## بوابات الجودة ذات القيمة

كل بوابة تعيد واحدة من ثلاث حالات: `مفتوحة` أو `تحتاج تحسين` أو `مغلقة`، مع سبب مفهوم وإجراء تالٍ. لا تستخدم درجة رقمية وحدها كحكم أكاديمي.

### قواعد الاتساق الأولى

- المشكلة يجب أن تشير إلى سياق أو دليل أو فجوة، لا إلى عنوان عام فقط.
- الفجوة لا تُعتمد إذا لم ترتبط بدراسات مختارة ومخزنة في المشروع.
- العنوان لا يُعتمد إذا خالف المشكلة أو المجتمع أو المتغيرات المعلنة.
- عند إضافة أهداف وأسئلة ومنهجية لاحقاً، يفحص النظام العلاقة: `مشكلة → أهداف → أسئلة → منهج → أداة`.
- إذا اختير منهج نوعي ثم اختيرت استبانة كمية، تظهر رسالة تعارض واقتراحان واضحان، ولا ينشئ النظام أداة توحي بصحة الاختيار.

## الحالة الحالية مقابل المطلوب

| المجال | الموجود | المطلوب قبل ادعاء اكتمال الـMVP |
| --- | --- | --- |
| الواجهة العامة والرحلة | موجودة بصرياً ومراحلها الأساسية موجودة | تبسيط نقطة البداية إلى نية مستخدم واحدة |
| الحماية | تحقق جلسة وملكية موارد واختبار A/B موجود | استمرار تغطية أي API جديد بنفس القاعدة |
| تخزين المراحل | بعض المخرجات تُحفظ ومخطط جداول الرحلة موجود | ترحيل جميع مخرجات الرحلة من Local Storage إلى سجل خادمي مع إصدارات وقرارات |
| الأدلة | بحث مصادر وتخليق أولي موجودان | حفظ المصدر المختار ومعرّفه وربطه بالفجوة |
| بوابات الجودة | شروط فتح شكلية موجودة | قواعد اتساق قابلة للتفسير وسجل قرار لكل بوابة |
| تصدير | تصدير للمشروع موجود | التصدير من مخرجات خادمية موثقة فقط |

## معايير القبول العملية

لا نعتبر Workflow ناجحاً قبل تحقق الآتي في جلسة مستخدم حقيقية:

1. لا يمكن فتح مرحلة الأدلة قبل وجود مشكلة.
2. لا يمكن اعتماد فجوة بلا مصادر محفوظة.
3. يظهر سبب الرفض أو التحسين بلغة بسيطة، مع رابط للمرحلة المطلوبة.
4. يمكن للمستخدم الخروج والعودة إلى نفس المشروع دون فقدان السياق.
5. لا يستطيع مستخدم آخر قراءة المشروع أو تعديل مخرجاته.
6. التصدير يطابق المشروع المحفوظ ولا يضيف نصاً أو مراجع غير موثقة.
